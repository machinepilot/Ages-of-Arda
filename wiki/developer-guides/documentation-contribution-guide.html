Documentation Contribution Guide

This guide explains how to add or modify documentation in the Ages of Arda documentation system. Follow these steps to ensure your contributions integrate smoothly with our unified documentation system.

Overview of the Documentation System

The Ages of Arda documentation system uses a single-source approach where content is written once in Markdown format and automatically converted to multiple output formats:

  • Wiki HTML pages (for our Netlify-hosted documentation)
  • Cursor rules (for IDE integration)
  • GitHub documentation (for repository documentation)

File Structure

All documentation source files are stored in the docs/_source directory, organized by section and category:

docs/
  _source/
    development/    # Developer-focused documentation
      architecture/ # System architecture docs
      guides/       # How-to guides and tutorials
      reference/    # API and code references
    gameplay/       # Player-focused documentation
      guides/       # Player guides and tutorials
      reference/    # Game mechanics references

Adding New Documentation

  1. Choose the right location: Determine whether your documentation is for developers (development) or players (gameplay), and choose the appropriate subcategory.

  2. Create a new Markdown file: Use this naming convention: descriptive-name.md. Use kebab-case (lowercase with hyphens).

  3. Add frontmatter: Every document must begin with YAML frontmatter that includes metadata:

---
title: "Your Document Title"
id: "unique-document-identifier"
section: "development|gameplay"
category: "guides|architecture|reference"
created: "YYYY-MM-DD"
updated: "YYYY-MM-DD"
version: "1.0.0"
---

  1. Write your content: Use Markdown for your document content. See the "Markdown Tips" section below.

  2. Build and test: Run the build process to ensure your document generates correctly.

Converting Documentation to Cursor Rules

To make your document also function as a Cursor rule (for IDE integration), add these fields to the frontmatter:

cursor_rule: true
glob: "**/*.ext"  # File pattern this rule applies to
priority: 500     # Rule priority (higher numbers run first)
rule_category: "category" # Directory within rules

Modifying Existing Documentation

  1. Locate the source file: Find the .md file in the docs/_source directory

  2. Update the frontmatter: Change the updated date and increment the version if making substantial changes

  3. Edit the content: Make your changes to the Markdown content

  4. Build and test: Run the build process to ensure your changes generate correctly

Building Documentation

To build the documentation after making changes:

# Navigate to the docs directory
cd docs

# Run the build script
node _scripts/build.js

This will process all documentation and generate the wiki, Cursor rules, and GitHub documentation.

Viewing Your Changes

After building:

  1. Wiki pages: Start a local web server in the wiki directory:

    cd wiki
npx http-server -p 3000

    Then navigate to http://localhost:3000 in your browser.

  2. Cursor rules: Open the .cursor/rules directory to see the generated rules.

Common Issues and Solutions

Path Issues

When referencing other documents or assets, use relative paths:

  • For links to other documentation: [Link text](../category/file-name.html)
  • For images in the wiki: ![Alt text](../images/image-name.png)

Frontmatter Validation

If the build fails due to frontmatter issues:

  • Ensure there's a space after the colon in each field
  • Check that all required fields are present
  • Verify the section and category values are correct

Line Endings

Ensure your files use consistent line endings (LF is preferred). Mixed line endings can cause issues with the frontmatter parser.

Future Documentation Plans

The documentation system will be expanded in the future to include:

  • A lore system that will integrate with the existing structure
  • Improved search capabilities
  • Additional output formats

When contributing, keep in mind that documentation may be repurposed for these future enhancements.

Getting Help

If you have questions or issues with the documentation system, contact the core development team or open an issue in the GitHub repository.
