Introduction for New Users

What is the Cursor Rules System?

The Cursor Rules System is an intelligent guidance framework that provides real-time development standards and best practices while you work in the Cursor editor. Think of it as having an expert looking over your shoulder as you code, offering advice specific to what you're working on.

Why Use It for Game Development?

Game development involves complex systems that must work together: graphics, AI, physics, user interface, storytelling, and more. The Cursor Rules System helps by:

  1. Automatically loading relevant guidelines based on the file you're editing
  2. Ensuring consistency across the codebase regardless of who's working on it
  3. Reducing cognitive load by providing patterns and solutions for common problems
  4. Improving code quality through standardized approaches
  5. Accelerating onboarding for new team members

How It Works in Simple Terms

When you open a file in Cursor, the system:

  1. Looks at the file path and type
  2. Finds matching rules based on glob patterns
  3. Presents those rules within Cursor
  4. Updates the guidance as you switch between files

For example, when editing an AI behavior file, you'll automatically see AI-specific guidelines, whereas editing a memory management file will show memory allocation best practices instead.

System Overview

The Cursor rules system is an integrated set of guidelines that are automatically applied based on the context of files being edited. Each rule provides specific guidance for developing different aspects of the Ages of Arda game.

Key Components

  • Metadata-Driven Rules: Each rule file contains metadata in a YAML frontmatter that determines when it applies
  • Context-Aware Activation: Rules are automatically loaded based on file paths and types
  • Hierarchical Organization: Rules are structured in logical categories
  • Priority System: Higher priority rules take precedence when multiple rules apply
  • Related Rules: Rules can explicitly reference other related rules

Rule Priorities Explained

The priority number determines which rules take precedence:

  • 1000-900: Master rules (always loaded)
  • 899-700: Domain rules (language/technology specific)
  • 699-500: Feature rules (feature-specific guidelines)
  • 499-300: Specialized rules (very specific contexts)
  • 299-100: Optional rules (guidelines that may not always apply)

Rule Categories

Code Style

  • C Programming: Standard formatting, naming conventions, memory management
    • Indentation: 4 spaces (no tabs)
    • Max line length: 120 characters
    • Braces: K&R style (opening brace on same line)
    • Function declarations: return type on separate line
    • Variable naming: snake_case
    • Constants: ALL_CAPS_WITH_UNDERSCORES
  • HTML: Markup standards and best practices

Game Mechanics

  • Angband Variant: Core game structure, entity systems, game state management
  • Memory Management: Resource allocation, ownership, tracking, optimization
  • Lore Management: World-building, canon adherence, discovery mechanisms

AI Systems

  • AI Gameplay: Integration of AI into game mechanics, emergent behavior
  • AI UX: User experience for AI-driven features, responsiveness, transparency
  • Multi-Agent: Agent types, communication patterns, coordination

Infrastructure

  • GitHub Workflow: Branch management, PR standards, CI/CD integration
  • Netlify Deployment: Configuration, environment setup, deployment processes

MCP (Model Context Protocol)

  • Integration: API standards, error handling, context management
  • Server Configuration: Service setup, deployment, monitoring

Getting Started

Setting Up the Rules System

  1. Clone the Repository 
    git clone https://github.com/your-org/ages-of-arda.git
cd ages-of-arda
  2. Ensure Cursor is Installed

    The Cursor editor is required to utilize this rules system. Download from https://cursor.sh if needed.

  3. Verify Rules Structure 
    ls -la .cursor/rules
  4. Initialize Self-Healing (Optional) 
    powershell -ExecutionPolicy Bypass -File .cursor/rules/self-healing/schedule-analysis.ps1

Working with the Rules System

  1. Open a File in Cursor 
    cursor src/game/ai/npc_behavior.c
  2. View Active Rules

    Look at the Rules panel in Cursor to see which rules have been automatically loaded.

  3. Follow Guidance

    As you code, follow the guidelines that appear in the Rules panel.

  4. Reference Related Rules

    Click on related rule links to explore connected guidelines.

Development Loop

The Ages of Arda development follows a structured loop that leverages the rules system at each step:

1. Feature Planning

  • Rule Reference: Review relevant rules for the feature domain
  • Standards Adherence: Ensure planned implementation will follow guidelines
  • Prerequisites: Identify related systems and dependencies

2. Initial Implementation

  • Active Guidance: Cursor loads appropriate rules while coding
  • Code Patterns: Follow established patterns from examples in rules
  • Consistency Check: Compare new code against standards in real-time

3. Testing and Validation

  • Quality Metrics: Apply standards from rules to evaluate implementation
  • Heuristic Validation: Check against common issues documented in rules
  • Edge Case Handling: Verify all scenarios outlined in rules are addressed

4. Code Review

  • Automated Checks: Verify compliance with style, memory, and other guidelines
  • Manual Inspection: Compare implementation against domain-specific best practices
  • Documentation Verification: Ensure proper documentation following rule standards

5. Iteration and Refinement

  • Feedback Loop: Incorporate review findings back into the code
  • Rules Refinement: Update rules if new patterns or best practices emerge
  • Knowledge Sharing: Document learnings from implementation

Self-Healing System

The Ages of Arda rules system includes a self-healing mechanism that learns from coding patterns and errors to continuously improve its guidance:

How the Self-Healing System Works

  1. Error Collection: The system monitors build logs, static analysis, and runtime errors
  2. Pattern Analysis: Similar errors are clustered by signature and common root causes identified
  3. Rule Generation: New rule proposals are created for common error patterns
  4. Human Review: Proposed rules are reviewed by developers before integration
  5. Continuous Improvement: The system tracks which rules reduce error rates
