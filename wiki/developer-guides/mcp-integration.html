Model Context Protocol (MCP) Integration Guidelines

Overview

The Ages of Arda project uses Model Context Protocol (MCP) to integrate AI-driven narrative generation and companion features. This document outlines the implementation patterns and best practices.

Server Architecture

Simple MCP Server

The primary implementation is simple-mcp-server.js, which provides:

  • File system access to the codebase
  • Template-based narrative generation
  • Memory storage for character experiences
// Example narrative generation endpoint
app.post('/mcp/tools/generateNarrative', async (req, res) => {
  try {
    const { event_type, event_data, character_id, style, tone } = req.body;
    // Generate narrative based on templates or AI
    let narrative = generateTemplateNarrative(event_type, eventData, style, tone);
    
    // Store in character memories
    if (character_id) {
      storeCharacterMemory(character_id, narrative);
    }
    
    res.json(narrative);
  } catch (error) {
    // Provide fallback response
    res.json({ 
      text: "The bard seems at a loss for words...",
      tone: "confused",
      is_spoken: true,
      importance: 30
    });
  }
});

Client Integration

The C client (mcp-client.c) provides a bridge between the game and the MCP server:

/**
 * Request AI-generated content with fallback
 */
narrative_text_t *
mcp_generate_narrative(mcp_client_t *client, const char *event_type,
                     const char *event_data, const char *character_id,
                     const char *style, const char *tone)
{
    // Try to get response from MCP server
    mcp_response_t *response = mcp_invoke_tool(client, "generateNarrative", json_params_str);
    
    // Process response or use fallback
    narrative_text_t *narrative = process_narrative_response(response);
    
    return narrative;
}

Implementation Patterns

Fallback Mechanism

Always implement fallback mechanisms for when the MCP server is unavailable:

char *
get_ai_response(game_state_t *state, const char *prompt_type, const char *context)
{
    char *response = NULL;
    
    /* Try primary AI system */
    response = mcp_request(state, prompt_type, context);
    
    /* Fall back to template if AI unavailable */
    if (response == NULL) {
        response = get_template_response(prompt_type, context);
    }
    
    return response;
}

Asynchronous Processing

Use asynchronous processing to avoid blocking the game:

bool
request_narrative_async(const char *event_type, const char *event_data)
{
    return mcp_generate_narrative_async(
        mcp_client,
        event_type,
        event_data,
        player_uuid,
        "standard",
        NULL,
        narrative_callback,
        NULL
    );
}

Memory Management

Store important character memories for future reference:

// Store character memories
function storeCharacterMemory(characterId, narrative) {
  if (!characterMemories[characterId]) {
    characterMemories[characterId] = [];
  }
  
  characterMemories[characterId].push({
    timestamp: new Date(),
    narrative: narrative.text,
    importance: narrative.importance
  });
  
  // Sort by importance
  characterMemories[characterId].sort((a, b) => b.importance - a.importance);
}

Companion UI Integration

The companion UI is integrated through the SDL2 interface:

/**
 * Initialize companion data for a subwindow
 */
errr
companion_init(struct subwindow *subwindow)
{
    /* Allocate companion data */
    subwindow->companion = mem_zalloc(sizeof(struct companion_data));
    
    /* Initialize MCP client */
    subwindow->companion->mcp_client = mcp_client_init(MCP_SERVER_URL, NULL);
    
    return 0;
}

/**
 * Render companion window
 */
void
render_companion_window(struct subwindow *subwindow)
{
    /* Render companion portrait */
    render_companion_portrait(subwindow);
    
    /* Render dialogue text */
    render_companion_dialogue(subwindow);
    
    /* Render interaction options */
    render_companion_options(subwindow);
}
