Lore Management System

The Canonical Knowledge Repository

The Lore Management System serves as the authoritative repository for canonical Tolkien lore within the Ages of Arda project. It ensures that all AI-generated content remains consistent with established Middle-earth history, geography, and character backgrounds across the First, Second, and Third Ages.

System Architecture

The Lore Management System consists of five key components that work together to provide accurate and contextually relevant lore to the game's AI systems:

Components

1. Lore Database

A structured collection of JSON files organized by age and entity type, containing canonical information from Tolkien's works. Each entry includes source attribution and temporal metadata.

2. Lore Manager (C)

Core C module that provides efficient access to the lore database, with caching and indexing for performance.

// src/mcp/lore/lore_manager.c
#include "angband.h"
#include "lore_manager.h"

// Initialize the lore management system
bool init_lore_system(void)
{
    // Load lore database index
    if (!load_lore_index()) {
        return false;
    }
    
    // Initialize lore cache
    init_lore_cache();
    
    return true;
}

// Retrieve lore entry by name and type
lore_entry_t *get_lore_entry(const char *name, lore_type_t type)
{
    // Check cache first
    lore_entry_t *cached = lore_cache_lookup(name, type);
    if (cached) {
        return cached;
    }
    
    // Load from database if not in cache
    lore_entry_t *entry = load_lore_entry(name, type);
    if (entry) {
        // Add to cache for future lookups
        lore_cache_add(entry);
    }
    
    return entry;
}

3. Lore Integration (Python)

Python module that provides higher-level lore processing, including context-aware retrieval and narrative integration.

# src/mcp/lore/lore_integration.py
import json
from typing import Dict, List, Optional

class LoreIntegration:
    def __init__(self, memory_bank):
        self.memory_bank = memory_bank
        self.current_age = "third"  # Default to Third Age
    
    def get_contextual_lore(self, entity_name: str, 
                           context: Dict) -> Dict:
        """
        Retrieve lore relevant to the current context
        """
        # Get base lore entry
        base_lore = self._get_lore_entry(entity_name)
        if not base_lore:
            return {}
        
        # Enrich with contextual information
        enriched_lore = self._enrich_with_context(
            base_lore, context)
        
        # Add relevant relationships
        enriched_lore = self._add_relationships(
            enriched_lore, context)
            
        return enriched_lore

4. MCP Endpoints

API endpoints that allow the MCP server to query the lore system for AI prompt construction.

# Lore-related MCP endpoints

GET /lore/entity/{name}
- Retrieves information about a specific named entity
- Parameters:
  - name: Entity name
  - type: Optional entity type filter
  - age: Optional age filter
- Returns: JSON object with entity information

GET /lore/context/{context_id}
- Retrieves contextually relevant lore for a given game context
- Parameters:
  - context_id: Current game context identifier
  - limit: Maximum number of lore entries to return
- Returns: JSON array of relevant lore entries

POST /lore/validate
- Validates generated content against canonical lore
- Body: JSON object containing content to validate
- Returns: Validation result with inconsistencies highlighted

5. Narrative Generator

Specialized component that uses lore to generate narratively consistent descriptions, dialogues, and quest elements.

# src/mcp/lore/narrative_generator.py
class NarrativeGenerator:
    def __init__(self, lore_integration, mcp_client):
        self.lore = lore_integration
        self.mcp = mcp_client
    
    async def generate_npc_dialogue(self, 
                                  npc_name: str, 
                                  player_context: Dict,
                                  dialogue_type: str) -> str:
        """
        Generate lore-consistent dialogue for an NPC
        """
        # Gather relevant lore
        npc_lore = self.lore.get_contextual_lore(
            npc_name, player_context)
        
        # Construct prompt with lore constraints
        prompt = self._build_dialogue_prompt(
            npc_name, npc_lore, player_context, dialogue_type)
        
        # Generate dialogue via MCP
        response = await self.mcp.generate_text(prompt)
        
        # Validate against lore for consistency
        validated = self.lore.validate_content(
            response, npc_lore)
        
        return validated

Lore Entry Format

The lore database uses a standardized JSON format for all entries, with specific fields depending on the entity type:

Field Description Required
name Primary identifier for the entity Yes
type Entity type (character, location, artifact, event) Yes
age Relevant age(s) (first, second, third, or multiple) Yes
description Brief summary (1-2 sentences) Yes
content Detailed information about the entity Yes
source Source material reference Yes
year Temporal information (can be range or point) No
relationships Connections to other entities No
locations Associated places (for characters, artifacts, events) No
aliases Alternative names for the entity No

Performance Optimizations

The Lore Management System employs several optimizations to ensure efficient operation:

  • Tiered Caching: Frequently accessed lore is cached in memory with a multi-level approach:
    • L1 Cache: Most recently used entries kept in fast access memory
    • L2 Cache: Secondary cache for frequently accessed but not immediate entries
    • Persistent Cache: Disk-based cache for less frequent access patterns
  • Indexing: Multiple indices for fast lookup by name, type, age, and relationships
  • Lazy Loading: Lore entries are loaded on demand rather than all at once
  • Contextual Preloading: Predictive loading of related lore based on current game context

Integration with Game Systems

The Lore Management System integrates with several game systems:

  1. Character Generation: Ensures character backgrounds align with the chosen age
  2. Quest Generation: Provides historical context for procedurally generated quests
  3. NPC Dialogue: Informs dialogue options and responses based on canonical relationships
  4. World Building: Guides the generation of locations, artifacts, and events
  5. Companion Characters: Provides personality traits and background knowledge for companions

Contributing to the Lore Database

Contributors to the lore database should follow these guidelines:

  1. All entries must have a verifiable source in Tolkien's published works
  2. Entries should be categorized by the appropriate age(s)
  3. Relationships between entities should be bidirectional where appropriate
  4. Non-canonical extensions should be clearly marked as such
  5. Temporal information should use consistent notation (YT for Years of the Trees, FA for First Age, etc.)
