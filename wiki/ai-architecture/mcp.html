Model Context Protocol (MCP)

The Communication Layer for AI Integration

The Model Context Protocol (MCP) is the standardized communication layer that connects the Angband game engine with local Large Language Models (LLMs) via Ollama. It enables AI-driven gameplay by providing a structured way to request and receive content from language models while maintaining performance, security, and reliability.

Core Concepts

The MCP is built around several fundamental concepts that enable seamless integration between a traditional game engine and modern AI systems:

Tools

Discrete functions that the game can request from AI models, such as generating dialogue, creating descriptions, or analyzing game situations.

Context Management

Structured approach to providing relevant information to the AI model while respecting token limitations.

Endpoints

Standardized API routes that handle specific types of requests, such as companion dialogue or lore retrieval.

Prompts

Carefully engineered instructions that guide the AI model to produce the desired output format and content.

Response Parsing

Systematic extraction and validation of AI-generated content to ensure it meets game requirements.

Fallback Mechanisms

Alternative pathways when AI generation is unavailable, ensuring the game remains playable offline.

Architecture

The MCP architecture consists of several components that work together to provide a reliable and efficient communication layer:

MCP Server

At the core of the system is the MCP server, which:

  • Runs as a separate process alongside the game
  • Listens for requests from the game engine
  • Communicates with Ollama for LLM access
  • Processes and validates responses
  • Handles error conditions and retries
  • Implements caching and performance optimizations

The server is implemented in a combination of C (for core functionality) and Python (for higher-level processing), allowing for both performance and flexibility.

C API

The C API provides low-level access to MCP functionality from the Angband game engine:

/**
 * Initialize the MCP server for game integration
 */
mcp_server_t *
init_mcp_server(const char *server_name, int port)
{
    mcp_server_t *server = malloc(sizeof(mcp_server_t));
    
    if (server == NULL) {
        return NULL;
    }
    
    server->name = strdup(server_name);
    server->port = port;
    server->tools = create_tool_registry();
    server->active = false;
    
    return server;
}

/**
 * Register a tool with the MCP server
 */
bool
register_mcp_tool(mcp_server_t *server, const char *tool_name, 
                 tool_handler_t handler, tool_params_t *params)
{
    if (server == NULL || tool_name == NULL || handler == NULL) {
        return false;
    }
    
    mcp_tool_t *tool = create_tool(tool_name, handler, params);
    
    if (tool == NULL) {
        return false;
    }
    
    return add_tool_to_registry(server->tools, tool);
}

Tool Registration

The MCP allows for dynamic registration of tools, each implementing specific gameplay functionality:

// Register a narrative generation tool
tool_params_t *params = create_tool_params();
add_string_param(params, "location", "Location name", true);
add_string_param(params, "context", "Additional context", false);

register_mcp_tool(server, "generate_narrative", generate_narrative_handler, params);

Request/Response Flow

The typical flow for an MCP interaction follows these steps:

  1. Game engine identifies need for AI-generated content (e.g., entering a new location)
  2. Engine calls appropriate MCP function with relevant parameters
  3. MCP server formulates a request to the LLM with appropriate context
  4. LLM generates a response via Ollama
  5. MCP server validates and processes the response
  6. Processed response is returned to the game engine
  7. Game engine incorporates the response into gameplay

MCP Endpoints

The MCP provides a comprehensive set of endpoints organized by functionality:

Companion System

Companion Dialogue

POST /ages/companion/dialogue

Parameters:

Name Type Required Description
companion_name string Yes The name of the companion
age string Yes The current age (e.g., "first_age")
topic string No Optional topic for the dialogue
relationship_level integer Yes The relationship level with the companion (1-10)

Response:

{
  "dialogue": "The stone halls of Moria still echo with the memories of my people, friend. I can almost hear the hammers on anvils and the songs of old. Let us tread carefully, for what dwells here now bears little love for the living.",
  "companion": "Gimli",
  "age": "third_age",
  "topic": "Moria"
}

Prompt Templates

One of the key innovations in the MCP is the structured prompt template system, which ensures consistent, high-quality outputs:

[GAME_STATE]
{game_state_json}
[/GAME_STATE]

[PLAYER_HISTORY]
{player_history_text}
[/PLAYER_HISTORY]

[WORLD_STATE]
{world_state_json}
[/WORLD_STATE]

[LORE_CONTEXT]
{relevant_lore_json}
[/LORE_CONTEXT]

[INSTRUCTION]
{specific_instruction}
[/INSTRUCTION]

These templates provide clear separation between different types of context, allowing for:

  • Modular context management (adding or removing sections as needed)
  • Clear instruction delineation for the LLM
  • Efficient token usage by prioritizing the most relevant context
  • Consistent output format across different requests

Performance Considerations

The MCP implements several performance optimizations to ensure a smooth gameplay experience:

Response Caching

Common responses are cached to avoid redundant LLM calls, dramatically improving response times for repeated requests.

Asynchronous Processing

Non-blocking request handling ensures the game remains responsive while waiting for LLM responses.

Request Batching

Similar requests are combined when possible to reduce overhead and improve throughput.

Template Fallbacks

Pre-defined templates provide immediate responses for time-sensitive operations when LLM generation would be too slow.

Model Selection

Different models are selected based on the complexity of the task and available system resources.

Connection Management

Robust handling of connection issues, retries, and fallbacks ensures reliability even with unstable LLM access.

Security Considerations

The MCP incorporates several security measures to protect the game and player data:

  • Input Sanitization: All input to the MCP server is sanitized to prevent injection attacks
  • Output Validation: All LLM outputs are validated before being incorporated into the game
  • Local Processing: Using Ollama for local LLM access avoids sending data to external services
  • Rate Limiting: Prevents abuse through excessive requests
  • Authentication: Ensures only authorized game instances can access the MCP server
  • Content Filtering: Ensures generated content adheres to game-appropriate standards

Testing and Validation

The MCP includes a comprehensive testing framework to ensure reliability:

  • Unit Tests: Verify the functionality of individual MCP components
  • Integration Tests: Ensure proper interaction between the game engine and MCP server
  • Mock LLM Tests: Test MCP functionality without requiring actual LLM access
  • Performance Benchmarks: Measure response times and resource usage
  • Validation Tests: Ensure response formats and content adhere to requirements
  • Edge Case Testing: Verify behavior under unusual or error conditions
