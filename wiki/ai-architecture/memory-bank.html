Memory Bank System

Persistent Context for AI-Driven Gameplay

The Memory Bank System is a specialized knowledge management framework that provides persistent context to the AI systems in Ages of Arda. It serves as the long-term memory for the game's AI agents, ensuring consistency, coherence, and continuity across gameplay sessions while preventing hallucinations and incorrect information.

Core Architecture

The Memory Bank System is organized into five main components, each focusing on a different aspect of game context:

Memory Components

Game State Context

Represents the current game state, including player location, inventory, abilities, and entity relationships. This component enables AI systems to understand the player's current situation and respond appropriately.

Player Experience

Captures player interaction patterns, preferences, and history. This allows for personalized gameplay experiences and ensures AI responses are consistent with the player's past actions and choices.

World Building

Contains lore, environment descriptions, cultural details, and NPC behaviors. This is the foundation for creating a rich, immersive world that aligns with Tolkien's legendarium.

AI Behavior Patterns

Documents successful and failed AI interaction patterns, enabling the system to learn from past experiences and improve over time. This component is crucial for refining AI-driven gameplay elements.

Technical Architecture

Provides system diagrams and data flow patterns that help the AI understand the technical capabilities and constraints of the game engine, ensuring generated content is compatible with the game's systems.

Lore Database

A comprehensive collection of canonical Tolkien lore, organized by age and entity type, with source attribution. This serves as the authoritative reference for narrative generation and world consistency.

Memory Access Patterns

The AI systems access the Memory Bank through a set of specialized interfaces:

Direct Query Interface

/**
 * Retrieve memory entries by query parameters
 */
memory_entry_t **
memory_bank_query(memory_bank_t *bank, query_params_t *params)
{
    if (bank == NULL || params == NULL) {
        return NULL;
    }
    
    memory_result_set_t *results = create_result_set();
    
    // Process query against each relevant memory component
    if (params->include_game_state) {
        query_game_state(bank, params, results);
    }
    
    if (params->include_world_building) {
        query_world_building(bank, params, results);
    }
    
    // Additional components as needed
    
    // Sort by relevance and return
    sort_by_relevance(results);
    
    return extract_entries(results);
}

Lore-Specific Interface

/**
 * Retrieve lore specific to an entity and age
 */
lore_entry_t *
memory_bank_get_lore(memory_bank_t *bank, 
                      const char *entity_name,
                      age_t age,
                      lore_detail_level_t detail_level)
{
    if (bank == NULL || entity_name == NULL) {
        return NULL;
    }
    
    // First try exact match for the specific age
    lore_entry_t *entry = find_lore_entry(bank, entity_name, age);
    
    // If not found, try aliases
    if (entry == NULL) {
        entry = find_lore_by_aliases(bank, entity_name, age);
    }
    
    // If still not found and entity exists across ages, get most relevant
    if (entry == NULL) {
        entry = find_cross_age_lore(bank, entity_name);
    }
    
    // Filter content based on detail level
    if (entry != NULL) {
        apply_detail_filter(entry, detail_level);
    }
    
    return entry;
}

Context Assembly Interface

/**
 * Assemble comprehensive context for AI prompt
 */
char *
memory_bank_assemble_context(memory_bank_t *bank, 
                             context_request_t *request,
                             size_t max_tokens)
{
    if (bank == NULL || request == NULL) {
        return NULL;
    }
    
    context_builder_t *builder = create_context_builder(max_tokens);
    
    // Add components based on request priorities
    if (request->include_current_state) {
        add_current_game_state(bank, builder, request->state_priority);
    }
    
    if (request->include_player_history) {
        add_player_history(bank, builder, request->history_priority);
    }
    
    if (request->include_lore) {
        add_relevant_lore(bank, builder, request->location, 
                          request->entities, request->lore_priority);
    }
    
    // Finalize and format context
    format_context(builder);
    
    return extract_context_string(builder);
}

Memory Update Mechanisms

The Memory Bank is continuously updated through several mechanisms:

Game Event Listeners

Key game events trigger automatic updates to the Memory Bank:

  • Location Discovery: When a player discovers a new location, its details are added to the player experience
  • NPC Interactions: Conversations and relationships with NPCs are recorded
  • Quest Completion: Major narrative achievements are logged
  • Player Choices: Significant decisions are stored to influence future AI responses
  • World Changes: Changes to the game world (e.g., political shifts, destroyed locations) are recorded

AI Feedback Loop

AI responses are evaluated and used to refine the Memory Bank:

  • Success Patterns: Successful AI interactions are recorded for future reference
  • Failure Patterns: Problematic responses are logged to avoid repetition
  • Player Reactions: Implicit and explicit player feedback affects future context assembly
  • Content Quality: Generated content is evaluated for lore accuracy and narrative quality

Lore Organization

The lore component of the Memory Bank is organized to maximize authenticity and narrative consistency:

Age-Based Organization

Lore is primarily organized by the four Ages of Arda:

  • First Age: From the awakening of the Elves to the War of Wrath
  • Second Age: From the defeat of Morgoth to the defeat of Sauron and the One Ring
  • Third Age: From the defeat of Sauron to the War of the Ring and departure of the Ring-bearers
  • Fourth Age: The Age of Men, following the departure of the Elves

Entity Type Categorization

Within each age, entities are categorized by type:

  • Characters: Historical and legendary figures
  • Locations: Physical places and realms
  • Items: Artifacts, weapons, and significant objects
  • Events: Battles, councils, journeys, and significant moments
  • Cultures: Peoples and their customs, languages, and traditions
  • Creatures: Races, monsters, and beings
  • Concepts: Ideas, forces, and metaphysical elements

Source Attribution

All lore entries include source attribution to distinguish between:

  • Primary Canon: Direct from Tolkien's published works (The Hobbit, The Lord of the Rings)
  • Secondary Canon: From posthumously published works edited by Christopher Tolkien (The Silmarillion, Unfinished Tales)
  • Tertiary Canon: From The History of Middle-earth series and other scholarly compilations
  • Game Extensions: Lore extensions created specifically for the game

This attribution system allows AI systems to prioritize more canonical sources and clearly mark game-specific extensions.

Context Assembly Pipeline

The integration between the Memory Bank and MCP involves a sophisticated context assembly pipeline:

  1. Request Analysis: The MCP analyzes the incoming request to determine context needs
  2. Context Specification: A detailed context request is formulated, specifying required components
  3. Memory Retrieval: The Memory Bank gathers relevant entries from across components
  4. Relevance Ranking: Entries are ranked by relevance to the current situation
  5. Context Formatting: Selected entries are formatted into the structured MCP prompt format
  6. Token Optimization: Context is trimmed to fit within token limits while preserving critical information
  7. Prompt Assembly: The formatted context is combined with the task-specific instruction
  8. Model Processing: The complete prompt is processed by the LLM via Ollama

Performance Optimizations

Several optimizations ensure the Memory Bank operates efficiently even with large amounts of data:

Content Caching

Frequently accessed memory entries are cached in memory for rapid access, with cache invalidation on updates.

Progressive Loading

Memory components are loaded progressively based on immediate needs rather than loading everything at startup.

Relevance Filtering

Sophisticated algorithms rank memory entries by relevance to minimize context size while maximizing usefulness.

Compression Techniques

Less frequently accessed information is stored in compressed formats and decompressed only when needed.

Incremental Updates

Only changed portions of memory entries are written during updates, reducing I/O operations.

Background Processing

Memory reorganization and optimization tasks run during idle periods to avoid impacting gameplay.

  • Community Contributions: Creating a framework for player-contributed lore that stays faithful to canon
  • Temporal Memory Dynamics: Implementing a system for memories to evolve and change over time
