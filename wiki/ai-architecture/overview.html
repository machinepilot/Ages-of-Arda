AI Architecture Overview

A Layered Approach to AI-Driven Gameplay

The Ages of Arda project employs a sophisticated AI architecture designed to create emergent, lore-accurate gameplay experiences. This architecture integrates local Large Language Models (LLMs) with the Angband game engine through a series of specialized components, each with distinct responsibilities.

Core Architecture

The AI system is built on four foundational pillars that work together to create a cohesive gameplay experience:

1. Model Context Protocol (MCP)

The communication layer that connects the game engine with local LLMs via Ollama.

  • Standardized API for AI interactions
  • Context management for coherent responses
  • Prompt engineering for consistent outputs
  • Response parsing and validation

Learn more about MCP

2. Multi-Agent Framework

A collection of specialized AI agents that handle different aspects of gameplay generation.

  • Narrative Agent for story and quests
  • Character Agent for NPCs and dialogue
  • World Agent for environment descriptions
  • Item Agent for unique item generation
  • Combat Agent for battle narration

Learn more about the Multi-Agent Framework

3. Memory Bank System

Persistent storage for game state, player history, and AI-generated content.

  • Game State Context for current world state
  • Player Experience for interaction patterns
  • World Building for environment details
  • AI Behavior Patterns for successful interactions
  • Technical Architecture for system diagrams

Learn more about the Memory Bank System

4. Lore Management System

Repository for canonical Tolkien lore to ensure accuracy and consistency.

  • Structured lore database by age and entity type
  • Source attribution for canonical information
  • Integration with narrative generation
  • Validation of AI-generated content
  • Performance optimizations for efficient access

System Integration

These four pillars integrate with the Angband game engine and with each other to create a cohesive AI-driven gameplay experience:

Integration Points

  1. Game Engine to MCP: The Angband engine communicates with the MCP server through a C client library, requesting AI-generated content at specific gameplay moments.
  2. MCP to Multi-Agent Framework: The MCP server routes requests to the appropriate specialized agent based on the content type needed.
  3. Agents to Memory Bank: Agents retrieve context from and store generated content in the Memory Bank to maintain consistency across interactions.
  4. Agents to Lore Management: Agents query the Lore Management System to ensure generated content aligns with canonical Tolkien lore.
  5. Memory Bank to MCP: The Memory Bank provides historical context to the MCP for enriching prompts with relevant information.

Data Flow

A typical AI interaction in the game follows this data flow:

  1. Trigger Event: A gameplay event (e.g., entering a new location, encountering an NPC) triggers a request for AI-generated content.
  2. Context Gathering: The game engine collects relevant context (player state, location, etc.) and sends it to the MCP server.
  3. Agent Selection: The MCP server routes the request to the appropriate specialized agent (e.g., World Agent for location descriptions).
  4. Context Enrichment: The agent enriches the context with information from the Memory Bank and Lore Management System.
  5. Prompt Construction: The agent constructs a specialized prompt using templates designed for the specific content type.
  6. LLM Generation: The prompt is sent to the local LLM via Ollama for content generation.
  7. Response Processing: The raw LLM response is parsed, validated, and transformed into a format usable by the game engine.
  8. Memory Update: The interaction and generated content are stored in the Memory Bank for future reference.
  9. Game Integration: The processed content is returned to the game engine and integrated into the gameplay experience.

Performance Considerations

The AI architecture includes several optimizations to ensure responsive gameplay:

  • Local LLM Execution: All AI processing occurs locally via Ollama, eliminating network latency and privacy concerns.
  • Asynchronous Processing: Non-blocking API calls allow the game to continue while waiting for AI responses.
  • Multi-level Caching: Frequently accessed content is cached at various levels to reduce redundant processing.
  • Fallback Mechanisms: Pre-generated content is used when real-time generation would cause delays.
  • Progressive Enhancement: AI features are implemented in a way that degrades gracefully on less powerful hardware.

Development Workflow

The AI architecture is developed using a modular approach that allows for incremental implementation and testing:

  1. Core Infrastructure: MCP server and basic communication with Ollama
  2. Foundational Components: Memory Bank and Lore Management systems
  3. Specialized Agents: Individual agents for different content types
  4. Integration Layer: Connecting all components with the game engine
  5. Optimization: Performance tuning and fallback mechanisms
  6. Expansion: Additional content types and enhanced capabilities

Future Directions

The AI architecture is designed to be extensible, with several planned enhancements:

  • Advanced Narrative Generation: More complex, branching storylines that adapt to player choices
  • Character Development: NPCs that evolve based on interactions with the player
  • Procedural Content: AI-generated dungeons, quests, and items with deeper lore integration
  • Multi-modal Integration: Incorporating image generation for character portraits and location visuals
  • Player Modeling: Adapting gameplay to individual player preferences and play styles
