Lore Management API

Overview

The Lore Management API provides access to the rich lore of Tolkien's world, organized by age and entity type. This API is designed to ensure lore accuracy and consistency throughout the game, while providing efficient access patterns for both C and Python code.

C API (lore_manager.h)

Core Functions

Initialize Lore Manager

/**
 * Initialize the lore manager with the specified memory bank path
 * 
 * @param memory_bank_path Path to the memory bank directory
 * @return Pointer to initialized lore_manager_t or NULL on failure
 */
lore_manager_t*
lore_manager_init(const char* memory_bank_path);

Get Lore Entry

/**
 * Retrieve a lore entry for the specified entity
 * 
 * @param manager Pointer to the lore manager
 * @param entity_name Name of the entity to retrieve
 * @param entity_type Type of entity (character, location, artifact, event)
 * @param age Age to search in (first_age, second_age, third_age, or NULL for all)
 * @return Pointer to lore_entry_t or NULL if not found
 */
lore_entry_t*
lore_manager_get_entry(lore_manager_t* manager, 
                      const char* entity_name,
                      const char* entity_type,
                      const char* age);

Get Random Lore

/**
 * Retrieve a random lore entry
 * 
 * @param manager Pointer to the lore manager
 * @param entity_type Type of entity or NULL for any type
 * @param age Age to search in or NULL for any age
 * @return Pointer to lore_entry_t or NULL if none available
 */
lore_entry_t*
lore_manager_get_random(lore_manager_t* manager,
                       const char* entity_type,
                       const char* age);

Search Lore

/**
 * Search for lore entries matching the query
 * 
 * @param manager Pointer to the lore manager
 * @param query Search query
 * @param entity_type Type of entity or NULL for any type
 * @param age Age to search in or NULL for any age
 * @param max_results Maximum number of results to return
 * @return Array of lore_entry_t pointers, NULL-terminated
 */
lore_entry_t**
lore_manager_search(lore_manager_t* manager,
                   const char* query,
                   const char* entity_type,
                   const char* age,
                   int max_results);

Free Lore Entry

/**
 * Free a lore entry
 * 
 * @param entry Pointer to the lore entry to free
 */
void
lore_manager_free_entry(lore_entry_t* entry);

Free Lore Manager

/**
 * Free the lore manager and all associated resources
 * 
 * @param manager Pointer to the lore manager
 */
void
lore_manager_free(lore_manager_t* manager);

Lore Entry Structure

/**
 * Structure representing a lore entry
 */
typedef struct lore_entry_t {
    char* name;              /* Name of the entity */
    char* description;       /* Short description */
    char* content;           /* Main lore content */
    char* source;            /* Source book or material */
    char* age;               /* Age (first_age, second_age, third_age) */
    int year;                /* Year within the age */
    bool is_canonical;       /* Whether this is from Tolkien's works */
    char* entity_type;       /* Type of entity */
    char** additional_fields; /* NULL-terminated array of additional field names */
    char** additional_values; /* NULL-terminated array of additional field values */
} lore_entry_t;

MCP Endpoints

Lore Endpoints

Character Lore

ages/lore/character

Required Parameters:

  • character_name: Name of the character
  • age: Age (optional, defaults to current age)

Response:

{
  "content": "Detailed character lore...",
  "source": "The Silmarillion",
  "age": "first_age",
  "year": 472,
  "is_canonical": true,
  "name": "Túrin Turambar",
  "description": "Tragic hero of the First Age"
}

Best Practices

Performance Optimization

  • Implement caching with LRU replacement for all lore queries
  • Use asynchronous processing for LLM-based generation where possible
  • Provide templated fallbacks for all LLM-based generation
  • Pre-load commonly accessed lore on initialization
  • Rate-limit LLM calls to prevent overwhelming the system

Error Handling

  • Always check return values from lore API functions
  • Provide meaningful error messages for failed queries
  • Implement fallback behavior for missing lore data
  • Log all errors with appropriate context
  • Handle network failures gracefully in MCP requests

Lore Consistency

  • Validate all generated content against canonical lore
  • Clearly mark non-canonical content
  • Ensure temporal consistency within ages
  • Maintain character consistency across interactions
  • Preserve cultural and racial characteristics from Tolkien's works

The Lore API is a critical component of the Ages of Arda project, ensuring that all game content remains faithful to Tolkien's world while enabling dynamic, AI-driven gameplay experiences. Proper use of this API will help maintain the immersive quality that makes Middle-earth such a compelling setting.
