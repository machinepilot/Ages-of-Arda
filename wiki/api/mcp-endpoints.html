Model Context Protocol (MCP) API Endpoints

Interfacing with AI Models

The Model Context Protocol (MCP) is the core system that enables Ages of Arda to leverage AI models for dynamic content generation, NPC interactions, and narrative development. This document outlines the API endpoints available for interacting with the MCP system.

API Overview

The MCP API follows RESTful principles and uses JSON for request and response payloads. All endpoints are available at the base URL:

http://localhost:8080/api/mcp/v1

For production deployments, the API is available at:

https://api.agesofarda.com/mcp/v1

The API is versioned to ensure backward compatibility as new features are added.

Authentication

All API requests require authentication using an API key. The key should be included in the request headers:

Authorization: Bearer YOUR_API_KEY

API keys can be generated and managed through the developer portal or configured locally for development.

Local Development

For local development, you can use the default development key specified in your mcp_config.json file:

{
    "api_key": "dev_key_local_only",
    "base_url": "http://localhost:8080/api/mcp/v1",
    "timeout_ms": 5000
}

Dialogue Generation

Generate NPC Dialogue

POST /dialogue/generate

Generates contextually appropriate dialogue for an NPC based on the current game state, player history, and NPC characteristics.

Request Body:
{
    "npc_id": "string",
    "player_id": "string",
    "context": {
        "location": "string",
        "time_of_day": "string",
        "current_quest": "string",
        "recent_events": ["string"],
        "relationship_level": "number"
    },
    "dialogue_type": "string",  // "greeting", "quest", "lore", "farewell", etc.
    "max_length": "number",     // Maximum length in tokens
    "tone": "string"            // Optional: "friendly", "hostile", "neutral", etc.
}
Response:
{
    "dialogue": "string",
    "follow_ups": ["string"],   // Potential player response options
    "metadata": {
        "tone": "string",
        "sentiment": "string",
        "key_topics": ["string"]
    }
}
Status Codes:
  • 200 OK - Dialogue generated successfully
  • 400 Bad Request - Invalid request parameters
  • 401 Unauthorized - Invalid or missing API key
  • 404 Not Found - NPC or player not found
  • 500 Internal Server Error - Server error

Continue Conversation

POST /dialogue/continue

Continues an existing conversation with an NPC, maintaining context from previous exchanges.

Request Body:
{
    "conversation_id": "string",
    "player_response": "string",
    "max_length": "number"
}
Response:
{
    "dialogue": "string",
    "follow_ups": ["string"],
    "conversation_state": "string",  // "ongoing", "concluding", "quest_offered", etc.
    "metadata": {
        "sentiment_shift": "string",
        "relationship_change": "number"
    }
}

Narrative Events

Generate Event

POST /narrative/event

Generates a narrative event based on the current game state and player history.

Request Body:
{
    "player_id": "string",
    "location": "string",
    "event_type": "string",     // "combat", "discovery", "encounter", "ambient"
    "intensity": "number",      // 1-10 scale
    "constraints": {
        "lore_alignment": "number",  // How strictly to adhere to established lore (1-10)
        "age_specific": "string",    // "first_age", "second_age", "third_age"
        "required_elements": ["string"]
    }
}
Response:
{
    "event_id": "string",
    "title": "string",
    "description": "string",
    "outcomes": [{
        "description": "string",
        "probability": "number",
        "consequences": [{
            "type": "string",
            "description": "string",
            "game_effect": "string"
        }]
    }],
    "metadata": {
        "lore_references": ["string"],
        "suggested_music": "string",
        "mood": "string"
    }
}

Resolve Event

POST /narrative/event/{event_id}/resolve

Resolves a previously generated narrative event based on player choices.

Request Body:
{
    "player_id": "string",
    "chosen_outcome": "string",
    "player_actions": ["string"],
    "random_factors": {
        "luck": "number",
        "skill_checks": [{
            "skill": "string",
            "result": "number"
        }]
    }
}
Response:
{
    "resolution": "string",
    "consequences": [{
        "type": "string",
        "description": "string",
        "game_effect": "string"
    }],
    "memory_entries": [{
        "type": "string",
        "content": "string",
        "importance": "number"
    }]
}

Lore Integration

Query Lore

GET /lore/query

Retrieves lore information relevant to the current context.

Query Parameters:
  • topic (string) - The lore topic to query
  • age (string) - The age context ("first_age", "second_age", "third_age")
  • detail_level (number, optional) - Level of detail (1-5)
Response:
{
    "topic": "string",
    "content": "string",
    "sources": ["string"],
    "related_topics": ["string"],
    "canonical": "boolean"  // Whether this is canonical Tolkien lore or game-specific
}

Adapt Lore

POST /lore/adapt

Adapts canonical lore to accommodate player actions while maintaining consistency.

Request Body:
{
    "topic": "string",
    "player_actions": ["string"],
    "world_state": {
        "age": "string",
        "major_events": ["string"],
        "altered_elements": [{
            "element": "string",
            "current_state": "string"
        }]
    },
    "constraints": {
        "flexibility": "number",  // 1-10, how much the lore can be adapted
        "preserve_outcomes": "boolean"
    }
}
Response:
{
    "original_lore": "string",
    "adapted_lore": "string",
    "justification": "string",
    "consistency_score": "number",  // 1-100
    "ripple_effects": [{
        "affected_element": "string",
        "description": "string",
        "severity": "number"
    }]
}

Memory Bank Operations

Store Memory

POST /memory/store

Stores a new memory in the Memory Bank system.

Request Body:
{
    "player_id": "string",
    "memory_type": "string",  // "event", "dialogue", "discovery", "achievement"
    "content": "string",
    "metadata": {
        "location": "string",
        "time": "string",
        "importance": "number",  // 1-10
        "entities_involved": ["string"],
        "age": "string"
    },
    "tags": ["string"]
}
Response:
{
    "memory_id": "string",
    "status": "string",
    "summary": "string"  // Condensed version for quick reference
}

Retrieve Memories

GET /memory/retrieve

Retrieves memories based on specified criteria.

Query Parameters:
  • player_id (string) - The player's unique identifier
  • types (array, optional) - Types of memories to retrieve
  • tags (array, optional) - Tags to filter by
  • importance_min (number, optional) - Minimum importance level
  • age (string, optional) - Age context
  • limit (number, optional) - Maximum number of memories to return
  • related_to (string, optional) - Entity or concept to find related memories
Response:
{
    "memories": [{
        "memory_id": "string",
        "memory_type": "string",
        "content": "string",
        "metadata": {
            "location": "string",
            "time": "string",
            "importance": "number",
            "entities_involved": ["string"],
            "age": "string"
        },
        "tags": ["string"],
        "relevance_score": "number"  // How relevant to the query
    }],
    "total_count": "number",
    "summary": "string"  // Optional contextual summary
}

Update Memory Importance

PATCH /memory/{memory_id}/importance

Updates the importance level of a stored memory.

Request Body:
{
    "new_importance": "number",  // 1-10
    "reason": "string"
}
Response:
{
    "memory_id": "string",
    "previous_importance": "number",
    "new_importance": "number",
    "status": "string"
}

Companion Interactions

Generate Companion Response

POST /companions/{companion_id}/response

Generates a contextual response from a companion character.

Request Body:
{
    "player_id": "string",
    "situation": "string",
    "prompt": "string",  // What the player said/did
    "context": {
        "location": "string",
        "current_quest": "string",
        "relationship_level": "number",
        "recent_events": ["string"],
        "companion_state": "string"  // "injured", "happy", "concerned", etc.

Response:
{
    "response": "string",

Update Companion Relationship

PATCH /companions/{companion_id}/relationship

Updates the relationship status between a player and companion.

Request Body:
{
    "player_id": "string",
    "change_amount": "number",  // Positive or negative

    "interaction_type": "string"  // "quest", "dialogue", "gift", "combat", etc.
}
Response:
{
    "previous_level": "number",
    "new_level": "number",
    "relationship_status": "string",  // "friendly", "trusted", "loyal", etc.

}

Error Handling

All API endpoints return standard HTTP status codes. In case of an error, the response body will contain additional information:

{
    "error": {
        "code": "string",
        "message": "string",
        "details": "string",
        "request_id": "string"  // For troubleshooting
    }
}

Common Error Codes

Code Description
invalid_request The request was malformed or missing required parameters
authentication_error Invalid or missing API key
resource_not_found The requested resource does not exist
model_error The AI model encountered an error during processing
rate_limit_exceeded Too many requests in a given time period
server_error An unexpected server error occurred

Usage Examples

Generating NPC Dialogue

Request:

  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \

    "npc_id": "elrond_001",

Rate Limits

To ensure service stability, the MCP API enforces rate limits:

Endpoint Category Rate Limit Reset Period
Dialogue Generation 60 requests 1 minute
Narrative Events 30 requests 1 minute
Lore Operations 100 requests 1 minute
Memory Operations 120 requests 1 minute
Utility Endpoints 300 requests 1 minute

Rate limit headers are included in all responses:

  • X-RateLimit-Limit: Total requests allowed in the period
  • X-RateLimit-Remaining: Requests remaining in the current period
  • X-RateLimit-Reset: Time when the rate limit resets (Unix timestamp)
